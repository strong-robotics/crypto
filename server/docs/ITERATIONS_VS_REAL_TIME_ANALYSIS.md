# Аналіз: Перехід від ітерацій до реального часу життя токена

## Поточна система: Ітерації

### Що таке "ітерація"?
**Ітерація** = кількість секунд життя токена з валідною ціною (`usd_price IS NOT NULL AND usd_price > 0`).

**Формула:**
```sql
SELECT COUNT(*) 
FROM token_metrics_seconds 
WHERE token_id=$1 
  AND usd_price IS NOT NULL 
  AND usd_price > 0
```

### Приклад:
- **Секунда 0:** токен створено, ціна = $0.001 → **ітерація 1**
- **Секунда 1:** ціна = $0.002 → **ітерація 2**
- **Секунда 2:** ціна = NULL (немає даних) → **не рахується**
- **Секунда 3:** ціна = $0.003 → **ітерація 3**
- **Секунда 4:** ціна = $0.000 (rug pull) → **не рахується** (usd_price = 0)

**Результат:** На 5-й секунді життя токена маємо **3 ітерації** (тільки секунди з валідною ціною).

---

## Нова система: Реальний час життя

### Що таке "реальний час життя"?
**Реальний час життя** = різниця між поточним часом та моментом створення токена (`first_pool_created_at` або `created_at`).

**Формула:**
```python
origin_ts = first_pool_created_at or created_at
live_seconds = int(time.time()) - origin_epoch
```

### Приклад:
- **Секунда 0:** токен створено (`created_at = 2024-01-01 12:00:00`)
- **Секунда 1:** ціна = $0.001 → **live_seconds = 1**
- **Секунда 2:** ціна = NULL → **live_seconds = 2** (все одно рахується!)
- **Секунда 3:** ціна = $0.003 → **live_seconds = 3**
- **Секунда 4:** ціна = $0.000 → **live_seconds = 4** (все одно рахується!)

**Результат:** На 5-й секунді життя токена маємо **5 секунд реального часу** (всі секунди, незалежно від ціни).

---

## Ключова різниця

| Аспект | Ітерації | Реальний час |
|--------|----------|--------------|
| **Що рахується** | Тільки секунди з `usd_price > 0` | Всі секунди від створення |
| **Пропуски даних** | Не рахуються | Рахуються |
| **Нульові ціни** | Не рахуються | Рахуються |
| **Залежність від даних** | Залежить від якості даних | Незалежна від даних |
| **Стабільність** | Може "застрягнути" при пропусках | Завжди зростає |

## Вплив на AI прогнози

### 1. Pattern Segments (сегменти паттернів)

**Поточна система:**
```python
# _v3_analyzer_jupiter.py
iterations_count = await get_token_iterations_count(conn, token_id)
segment_dicts = feature_vector_for_segments(series)

# Сегменти: 0-35, 35-85, 85-125 (ітерації)
if iterations_count < segment_end:
    predicted.append("unknown")
```

**Проблема з ітераціями:**
- Якщо токен має пропуски в даних (наприклад, 50% секунд без ціни), то:
  - На реальній 70-й секунді маємо тільки 35 ітерацій
  - Другий сегмент (35-85) не може бути розрахований
  - AI не може зробити прогноз

**З реальним часом:**
- На реальній 70-й секунді маємо `live_seconds = 70`
- Другий сегмент (35-85) може бути розрахований
- AI може зробити прогноз, навіть якщо є пропуски

**Вплив:** ✅ **Позитивний** - більше токенів отримають прогнози

---

### 2. ETA Model (прогноз виходу)

**Поточна система:**
```python
# ai/infer/eta_online.py
iterations = await _age_now(conn, token_id)  # COUNT(*) WHERE usd_price > 0
window_size = ENTRY_SEC if has_real_pos else AI_PREVIEW_ENTRY_SEC
recents = await _last_window(conn, token_id, window_size)
```

**Проблема з ітераціями:**
- ETA модель потребує `window_size` точок даних
- Якщо `window_size = 950` (AUTO_BUY_ENTRY_SEC), але токен має пропуски:
  - На реальній 1000-й секунді маємо тільки 600 ітерацій
  - Недостатньо даних для прогнозу
  - Автопокупка не спрацює

**З реальним часом:**
- На реальній 1000-й секунді маємо `live_seconds = 1000`
- Можна взяти останні 950 секунд даних (навіть з пропусками)
- ETA модель може працювати з неповними даними

**Вплив:** ✅ **Позитивний** - більше токенів отримають ETA прогнози

### 3. Автопокупка (1 година 20 хвилин = 4800 секунд)

**Поточна система:**
```python
# _v3_analyzer_jupiter.py
iterations_count = await get_token_iterations_count(conn, token_id)
if iterations_count >= self.entry_sec:  # AUTO_BUY_ENTRY_SEC = 950
    if decision == "buy":
        await buy_real(token_id)
```

**Проблема з ітераціями:**
- Якщо `AUTO_BUY_ENTRY_SEC = 4800` (1 година 20 хвилин), але токен має пропуски:
  - На реальній 5000-й секунді маємо тільки 3000 ітерацій
  - Умова `iterations >= 4800` не виконується
  - Автопокупка не спрацює, навіть якщо токен "доріс" до потрібного віку

**З реальним часом:**
- На реальній 5000-й секунді маємо `live_seconds = 5000`
- Умова `live_seconds >= 4800` виконується
- Автопокупка спрацює точно в потрібний момент

**Вплив:** ✅ **Позитивний** - автопокупка спрацьовує точно за часом

## Вплив на архівування та очистку

### 1. ARCHIVE_MIN_ITERATIONS (1000 ітерацій)

**Поточна система:**
```python
# _v2_buy_sell.py
if iteration_count >= ARCHIVE_MIN_ITERATIONS:  # 1000
    await archive_token(token_id)
else:
    await purge_token(token_id)
```

**Проблема з ітераціями:**
- Токен може жити 2 години (7200 секунд), але мати тільки 800 ітерацій
- Не архівується (потрібно 1000), але вже занадто старий
- Займає місце в базі даних

**З реальним часом:**
- Якщо `ARCHIVE_MIN_ITERATIONS = 3600` (1 година):
  - Токен з `live_seconds = 7200` буде архівований
  - Незалежно від кількості ітерацій

**Вплив:** ✅ **Позитивний** - більш справедливе архівування за часом

---

### 2. Zero Tail Detection

**Поточна система:**
```python
# _v3_analyzer_jupiter.py
# Останні 120 ітерацій з нульовою ціною
if pos_cnt == 0:  # 120 послідовних ітерацій з нульовою ціною
    await _flag_zero_tail(total_points)
```

**Проблема з ітераціями:**
- Якщо токен має пропуски, то "останні 120 ітерацій" можуть бути розтягнуті на 200+ секунд реального часу
- Zero tail може не спрацювати, якщо є пропуски між нульовими цінами

**З реальним часом:**
- "Останні 120 секунд" - це точно 120 секунд реального часу
- Zero tail спрацює точно через 120 секунд нульових цін

**Вплив:** ✅ **Позитивний** - більш точне виявлення мертвих токенів

---

### 3. Frozen Price Detection

**Поточна система:**
```python
# _v3_analyzer_jupiter.py
# Останні 120 ітерацій з однаковою ціною
if max(prices) - min(prices) <= eps:
    frozen_triggered = True
```

**Проблема з ітераціями:**
- Аналогічно zero tail - "останні 120 ітерацій" можуть бути розтягнуті на більший період

**З реальним часом:**
- "Останні 120 секунд" - це точно 120 секунд реального часу
- Frozen price спрацює точно через 120 секунд однакової ціни

**Вплив:** ✅ **Позитивний** - більш точне виявлення заморожених токенів

## Проблеми переходу на реальний час

### 1. Неповні дані для AI

**Проблема:**
- AI моделі навчені на повних даних (кожна секунда має ціну)
- При переході на реальний час можуть бути пропуски в даних
- AI може отримати неповний віктор признаків

**Рішення:**
- Використовувати forward-fill або interpolation для пропусків
- Або навчити AI моделі працювати з пропусками

---

### 2. Різні швидкості накопичення даних

**Проблема:**
- Токен A: 100% секунд з ціною → `iterations = live_seconds`
- Токен B: 50% секунд з ціною → `iterations = live_seconds / 2`
- При `live_seconds = 4800`:
  - Токен A має 4800 точок даних
  - Токен B має тільки 2400 точок даних
- AI прогноз для токена B може бути менш точним

**Рішення:**
- Додати перевірку мінімальної кількості точок даних перед прогнозом
- Або використовувати відносну щільність даних як ознаку

---

### 3. Зміна логіки сегментів

**Проблема:**
- Поточні сегменти: 0-35, 35-85, 85-125 (ітерації)
- При переході на реальний час: 0-35, 35-85, 85-125 (секунди)
- Якщо токен має пропуски, сегменти можуть містити менше даних

**Рішення:**
- Зберігати сегменти в ітераціях (для AI)
- Але використовувати реальний час для перевірки віку токена

---

## Гібридний підхід (рекомендація)

### Комбінована система:

1. **Реальний час** (`live_seconds`) - для:
   - Перевірки віку токена (`live_seconds >= 4800`)
   - Архівування (`live_seconds >= 3600`)
   - Zero tail / Frozen price detection (останні N секунд)
   - Автопокупка (точний час входу)

2. **Ітерації** (`iterations_count`) - для:
   - AI прогнозів (потрібні повні дані)
   - Pattern segments (потрібні повні дані)
   - ETA модель (потрібні повні дані)
   - Мінімальна перевірка: `iterations_count >= min_required` перед AI прогнозом

### Приклад реалізації:

```python
# Перевірка віку для автопокупки
live_seconds = calculate_live_seconds(token_id)  # Реальний час
if live_seconds >= AUTO_BUY_ENTRY_SEC:  # 4800 секунд
    # Перевірка достатності даних для AI
    iterations_count = await get_token_iterations_count(conn, token_id)
    min_data_points = int(AUTO_BUY_ENTRY_SEC * 0.7)  # 70% даних мінімум
    if iterations_count >= min_data_points:
        # AI може зробити прогноз
        decision = await ai_predict(token_id)
        if decision == "buy":
            await buy_real(token_id)
    else:
        # Недостатньо даних - пропускаємо
        pass
```

## Конкретні зміни для реалізації

### 1. Автопокупка (1 година 20 хвилин = 4800 секунд)

**Замість:**
```python
iterations_count = await get_token_iterations_count(conn, token_id)
if iterations_count >= AUTO_BUY_ENTRY_SEC:  # 950
```

**Використовувати:**
```python
live_seconds = calculate_live_seconds(token_id)  # Реальний час
if live_seconds >= 4800:  # 1 година 20 хвилин
    # Перевірка достатності даних
    iterations_count = await get_token_iterations_count(conn, token_id)
    min_data_ratio = 0.7  # 70% даних мінімум
    if iterations_count >= int(live_seconds * min_data_ratio):
        # AI прогноз та автопокупка
```

### 2. Архівування (1 година = 3600 секунд)

**Замість:**
```python
if iteration_count >= ARCHIVE_MIN_ITERATIONS:  # 1000
```

**Використовувати:**
```python
live_seconds = calculate_live_seconds(token_id)
if live_seconds >= 3600:  # 1 година
    await archive_token(token_id)
```

### 3. AI прогнози

**Зберігати ітерації для AI, але додати перевірку:**
```python

iterations_count = await get_token_iterations_count(conn, token_id)

# Мінімальна щільність даних (70%)
min_data_ratio = 0.7
if iterations_count >= int(live_seconds * min_data_ratio):
    # AI може зробити прогноз
    decision = await ai_predict(token_id, iterations_count)
else:
    # Недостатньо даних - пропускаємо

```

## Вплив на точність прогнозів

### Сценарій 1: Токен з повними даними (100% секунд з ціною)

**Ітерації:** `iterations = live_seconds`  
**Вплив:** ✅ Немає змін - все працює як раніше

### Сценарій 2: Токен з пропусками (50% секунд з ціною)

**Ітерації:** `iterations = live_seconds / 2`  
**Вплив:** 
- ✅ Автопокупка спрацює точно в потрібний момент (1 година 20 хвилин)
- ⚠️ AI прогноз може бути менш точним (менше даних)
- ✅ Рішення: перевірка мінімальної щільності даних перед AI

### Сценарій 3: Токен з великими пропусками (20% секунд з ціною)

**Ітерації:** `iterations = live_seconds * 0.2`  
**Вплив:**
- ✅ Автопокупка спрацює точно в потрібний момент
- ❌ AI прогноз може бути неточним (дуже мало даних)
- ✅ Рішення: не робити AI прогноз, якщо щільність < 50%
